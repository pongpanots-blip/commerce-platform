ไม่มีรอบสั่งซื้อ

ไม่พบข้อมูลรอบสั่งซื้อที่ตรงกับเงื่อนไขการค้นหา หรือยังไม่มีข้อมูลส่งมาจาก ERP

หน้า 1 จาก 1 (แสดง 4 รายการ, จำนวนหน้าสูงสุด: 1)

ข้อกำหนดการจัดการรอบสั่งซื้อ Supplier (Order Periods Protocol)

1 ที่มาข้อมูลและการนำเข้า (ERP Inbound)

รอบสั่งซื้อสินค้าสั่งล่วงหน้า (Pre-order / Made-to-order) นำเข้าอัตโนมัติจากระบบ SAP / ERP ผ่าน API PUT /erp/order-periods โดยระบุรหัส supplier, วันส่ง และเวลาปิดรับคำสั่งซื้อ

2 การตรวจสอบขณะสั่งซื้อ (Checkout Validation)

ระบบ josh (Storefront Checkout Engine) จะเรียกใช้ข้อมูลรอบนี้เพื่อตรวจสอบเวลาปิดรับ (Cut-off Time) ก่อนที่ลูกค้าจะกดยืนยันออเดอร์ หากเกินเวลาปิดรับ ระบบจะขยับรอบส่งไปรอบถัดไปโดยอัตโนมัติ

3 การซิงค์ข้อมูลย้อนกลับ (Resync Actions)

หากข้อมูลในหน้าร้านไม่ตรงกับ ERP เจ้าหน้าที่สามารถกดปุ่ม "ส่งให้ josh อีกครั้ง" เพื่อส่ง payload สดเข้าไปยังคิวอัปเดตแคชรอบสั่งซื้อทันทีโดยไม่ต้องรอรอบ batch

✓
ส่งรอบสั่งซื้อให้ josh เรียบร้อยแล้ว

ส่งข้อมูลรอบสั่งซื้อให้ josh (Storefront Sync)

ระบบจะทำการอ่านข้อมูลรอบสั่งซื้อล่าสุดจากตาราง ERP แล้วทำการส่ง (Broadcast) ไปยัง Storefront Cache เพื่อให้หน้าร้านแสดงวันส่งและเวลาปิดรับตรงกันทันที

เป้าหมายปลายทาง: storefront-checkout / josh
จำนวนรอบสั่งซื้อ: 4 รอบ (Active Suppliers)
โหมดการซิงค์: Immediate Cache Eviction
ข้อควรระวัง: การกดส่งจะล้างแคชรอบสั่งซื้อของผู้ใช้ที่กำลังอยู่ในขั้นตอน checkout ทันที
