# Commerce Platform — task-based UI

Design for Thai commerce operations teams. The product has seven work areas:
สินค้าและสต็อก, ออเดอร์และการเงิน, ลูกค้าและบริการ, การตลาด, รายงานและข้อมูล,
ระบบเชื่อมต่อ, ตั้งค่าและทีมงาน. A separate developer portal manages API keys and webhooks.

## Visual language

- Light canvas `#f6f8fc`, white cards, restrained borders `#e1e7f0`.
- Primary blue `#365cf5`; ink `#17243b`; secondary text `#52627a`.
- Success `#157347`, warning `#b08900`, error `#c2333f`; always pair color with text.
- Noto Sans Thai for Thai and Latin; body 14px, labels 13px, page titles 28px.
- Cards have 12px corners; controls 8px. Use 16/24/32px spacing.
- A 256px sidebar, compact contextual header, and a readable content width near 1240px.
- SVG icons and local fonts in the application. No decorative stock photos or gradients.
- Phone layouts stack cards and collapse navigation. Scroll wide tables inside their panel.

## Usability

- Lead with the task and one primary action. Show records before creation forms.
- Organize each work area's links into short task sections, with useful descriptions.
- Creation and editing use named dialogs, clear labels, inline errors, and Cancel/Save actions.
- Keep keyboard focus inside dialogs, support Escape, and return focus to the trigger.
- Record links open their own detail URLs; preserve existing routes and role restrictions.
- Show loading, empty, filtered-empty and failed states separately.
- Counts and operational status in the application must come from its API. Prototype samples
  must be labeled `ข้อมูลตัวอย่าง`; never copy sample figures into application code.
- List APIs for platform products/customers support pagination only. A frontend search must
  explicitly say it searches the current page. Do not imply a complete catalog search.
- Every action in the application must work. Do not add export/import, bulk changes, charts,
  advanced filters or copy-secret actions without an existing supported API.

## Business fields and workflows

- Product list: SKU, name, status. Create/edit: SKU, name, description. Product detail also
  shows fulfillment mode, lead time, update date and inventory by warehouse when available.
- Customer list: name/code, email, phone, status. Detail shows contact data and actual orders.
- Orders: code, status, total, creation date. Create with customer/product selectors,
  editable quantity/unit price, add/remove lines and a calculated subtotal.
- Stock movements: receive, count, damage/return/correction, transfer. Choose an owned
  warehouse, enter SKU/quantity/note, show a clear explanation of the selected movement.
- Marketing: planning, campaigns/promotions, content/communication, tracking results.
- Reports: select a business/system report and its existing filters; show unavailable data
  honestly, with a retry action where supported.
- Connections: connections, inbound data, sync jobs, outgoing deliveries and failed records.
- Team settings: staff list, create account, role management and existing password/status actions.
- Portal: active key/webhook onboarding, key creation with the existing one-time secret,
  subscriptions, webhook test results, and recent delivery status filters.
