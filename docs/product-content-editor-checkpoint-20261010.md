## Persistence and source boundary

Admin, MER and Graphic retain their existing product-update authority. Other roles cannot read, review, recover or submit this content task. New reads are `GET /product-content-editor/items/:productId` and `GET /product-content-editor/requests/:id`; `POST /product-content-editor/review` does not write. The sole save route is the existing `POST /josh/products/:id/update`, with an optional strict `{ fields, contentEdit: { requestId, sku, version } }` envelope. The route identity and server staff identity are authoritative; commercial, master, status, identity and extra body fields are rejected in that envelope. Legacy bodies retain their existing behavior.

Native edit, complete `product.content.snapshot` outbox event and immutable actor/request receipt commit in one transaction using existing receipt tables. Existing native content writers share the SKU lock. A short shared catalog table lock prevents another catalog ID from being inserted, reactivated or re-keyed into the SKU during commit; existing selected mappings and native rows are also locked. New-flow lock waits have a 1.5-second per-lock limit and return an unavailable result without partial persistence. This briefly delays catalog writes during the content transaction; no uniqueness migration or catalog business rule was introduced.

The reviewed version binds exact product ID/SKU, ownership, catalog revision and the full native content row. Changed text, commercial fields, catalog mapping or catalog revision invalidates the review. Duplicate requests replay their original committed receipt even after later changes or ownership cutoff. Successful local storage or a successful review cannot establish completion; the UI checks the persisted original receipt before showing “Saved.” Shop delivery remains unverified.

Owned native reads never use copied text as editing defaults. Missing row, missing key, explicit null, stored empty text and failed source are distinct. SQL/read failures have error/retry states. The legacy report's owned content/master/logistics failures now block editing, and only genuine 404 absence is treated as missing. Provenance and row timestamps are shown without claiming source freshness. The maintenance importer remains outside the ordinary native-writer advisory lock convention.

Names and text keep the existing trimming, null and JavaScript string-length rules: nonblank names up to 255 UTF-16 code units and optional text up to 20,000. No price/cost normalization, activation, master approval, CS, credit or OCR logic was changed.

## Remaining source and BA work

This editor needs commerce content ownership and a known local product-ID/SKU catalog mapping. It does not infer missing content or prove downstream shop delivery. Product currency, tax, normalized cost UOM, stock UOM, observation freshness and trusted organization scope remain unresolved source contracts from the accepted evidence slice.

MER handoff/history remains accepted comparison-read context with no additional fields or actions. BA remains static guided preview: no actual journey editor, production source provider, live audience counts, personalization or daily trends. Its next contracts remain branch approval/birth/eligibility, accepted order identity, server branch/tenant grants, complete-history and late-arrival watermarks, consent/retention/deletion and a trusted live projection. Welcome and the other accepted slices were preserved; BA browser and unrelated production workflows were not rerun here.

The next product step is user acceptance of this six-field journey, then a separately scoped decision about other full-form fields. Expanding monetary editing or BA journeys requires the missing domain contracts first.
